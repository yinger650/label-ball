# 下一轮足球标注工具迭代 Plan

日期：2026-10-21  
状态：待实施；本文只定义方案，不代表工具已经具备以下能力。  
范围：ball-label MCP、共享出图工具、ball-label skill，以及必要的服务端领包策略。

## 1. 目标与本轮证据

保留当前「比赛上下文 → RGB 定位 → 直接球心坐标 → 保存结果视觉复核 → AI 审核」路线，优先减少漏标和坐标换算错误，再减少重复搜索与工具调用成本。

本轮 gpt-6.1 完成 18 包、1,800 个目标帧，其中 1,698 帧可见、102 帧不可见，提交编号 255–272。所有提交均进入 AI 审核，尚不能把完成率或本地复核当作准确率。明细见 `artifacts/label-trials/quota-run-20261020.json`。

观察到的问题：

- 两个明确的漏标修正：提交 271 的 22457 帧、提交 272 的 9160 帧，原标 absent，复核后找到了球。
- 当前 `coordinate_review.py` 对 absent 帧沿用最近可见点的裁剪中心；球快速移动时可能已在窗外。该窗只能提示检查区域，不能证明整帧不可见。
- 夜场小球、贴脚球、运动拖影易与球鞋、白线和背景亮点混淆。放大有帮助，但本轮依赖临时脚本，需手工扣标题、拼图偏移和缩放比例。
- `client/mcp_server.py` 中部分 plan/scan/strip 描述仍引导旧的 nominate/fit 或 480→80→45 流程，与现行 skill 不一致。
- 8 个定位困难的包多次返回同一工作者。服务端已有失败冷却，但只识别部分字符串原因；skill 示例 `cannot_locate` 与调度识别条件不完全一致。
- 静止球允许标，但「球在中圈」本身不足以证明是比赛球，应记录比赛身份依据和无法消除的疑点。

## 2. 不变原则

1. 只标比赛使用的球；静止球也可标，备用球不标。
2. RGB 与球员动作提供最终视觉依据；scan、滤波、轨迹和插值只辅助寻找。
3. 不增加模型置信分或 verify 分数筛选，不用平滑程度证明答案正确。
4. 每个最终坐标必须来自该帧的观察；未查看的帧保持未标，不填 absent。
5. absent 表示该目标帧无法看见比赛球，不等于当前裁剪窗找不到球。
6. 逐帧检查实际保存的标签；改标后复核受影响内容。所有结果继续以 `source=ai` 进入审核。
7. 本轮不更换模型、不增加自动插值标注，也不默认扩大到模型训练或完整工作台重写。

## 3. MCP 与辅助工具改动

以下工具名和字段为建议接口，实施时统一 schema，并更新说明与测试。

### P0-A：统一原图坐标视图

把 `coordinate_review.py` 的渲染与 manifest 逻辑提取为共享模块，CLI 与 MCP 调用同一实现，避免两套坐标规则。新增 `ball_coordinate_view`：

```json
{
  "packet_id": "…",
  "frames": [100, 103, 106],
  "center": [3200, 1100],
  "size": 480,
  "scale": 1,
  "max_page_pixels": [1440, 1600]
}
```

- 主视野保留 320–480 px 原始范围和球员上下文；800 px 允许用于扩大搜索。
- 支持 1×、2×最近邻显示放大；放大不增加原图信息，也不能替代上下文。
- 按页面像素预算分页，避免大拼图被查看器自动缩小。每页、每帧返回原图尺寸、ROI 原点、图像区偏移、tile 原点、显示比例与有效 ROI 范围。
- 单独返回图片引用与精简元数据；默认不反复输出整包 100 帧的长列表。
- 新增显式页面坐标换算接口，例如 `ball_resolve_point(view_id, frame_idx, image_index, image_xy)`，返回 `roi_xy`。坐标以生成图片的原始像素计；如果查看器仍缩放，调用者必须提供已知变换或切换单图，不能猜显示比例。
- 换算接口不写标签。验证 packet、frame、图片归属，拒绝标题区、其他 tile 和 ROI 外黑边；全景接缝转换继续复用现有实现。
- `ball_label(roi_xy)` 保持兼容；不改变旧 cell 接口优先级。本轮通过显式换算和参数检查减少混用风险。

验收：1×/2×、分页、负裁剪原点、标题边界和 ERP 接缝均有坐标回算测试；错误 view/frame 和越界点击明确报错；原图不经生成式增强。

### P0-B：把实际标签复核接入 MCP

新增 `ball_review`，直接读取当前会话实际保存的 labels，默认覆盖全部目标帧，输出：

- 所有目标帧的圆圈叠加页，明确区分 visible、absent、unlabeled。
- 带缺口断线的轨迹图；长轨迹支持分段显示，避免帧号挤在一起。
- `missing_frames`、`absent_frames`、本次标签快照哈希、review ID 和页面索引。
- 对 absent 帧额外生成专项复核材料：该帧扩大上下文、前后目标帧，以及按需查看完整 ROI 的入口。最近可见点只作为搜索中心，并显式标注「并非全帧搜索」。

球超出预测位置时允许人工移动搜索窗；不得只扩大固定窗后就自动确认 absent。标注者需结合完整 ROI、前后动作检查可能的飞行、反弹和遮挡位置。球仍在 ROI 内但出界时继续标；ROI 外无法观察的球记不可见，不编造坐标。

本地增加复核确认记录，例如 `ball_review_ack(review_id, page_ids, absent_frames_checked, trajectory_checked)`。这只记录标注者声明，不证明图片已被模型理解，更不证明标注正确。

- 复核绑定标签快照；标签或目标帧变化使旧确认失效，重新生成受影响页面与轨迹。
- 下一轮先以提示模式接入，确认兼容现有客户端后，再在新版视觉复核路径要求有效 review ID 和完整覆盖。
- 保留旧接口兼容期，不静默改变历史提交方式；新路径不借 `force` 绕过缺帧、全不可见和复核要求。
- 服务端仍审核；复核记录可随结果归档，不能变成免审凭证。

验收：用 22457、9160 两个已知案例验证扩大上下文能覆盖真实球位置；缺帧不会消失；改标后旧复核失效；提交仍为 `source=ai`，不触发置信分筛选。两个案例只验证流程，不用于宣称整体准确率。

### P0-C：统一工具提示与输出

同步 `client/mcp_server.py` 的工具描述、`AgentSession.plan` 等动态 next/hint、skill、references 和 Codex adapter：

- 主路线统一为 overview/scan → RGB 连续坐标视图 → label/absent → review → submit。
- 旧 nominate/fit/follow/commit 保留兼容，但不再作为默认下一步。
- scan/增强图只辅助搜索；移除将 80/45 小窗作为主视野的建议。
- `ball_plan` 默认返回计数、下一组目标帧和必要事件上下文；完整列表提供显式参数或分页，保证客户端最终仍能遍历全部目标帧。
- 提交成功返回 submission ID、目标帧覆盖、可见/不可见数量、审核状态；错误返回可操作的下一步。

验收：新会话的默认工具描述和动态提示均不将标注者引回旧路线；旧接口仍可调用；精简输出无目标帧遗漏。

### P1-A：困难包释放与重领

修改 `server/db.py` 相关调度、API 与 MCP 参数，区分标注困难和基础设施失败：

- `reason_code` 建议包括 `cannot_locate`、`lost_after_occlusion`、`ambiguous_match_ball`、`download_error`、`decode_error`、`user_stop`，另有自由文本 `note`。
- 保留旧 `reason` 字符串兼容映射；不再依赖加 `error:` 前缀才能获得冷却。
- 领包支持有上限的会话排除列表。当前会话明确失败的困难包不反复自动发回；不会永久拉黑，也不阻止其他方法或人工处理。
- 下载/解码错误使用独立的有限重试与退避；不能将网络错误计为模型标注能力失败。
- 本地失败记录跨上下文恢复；无可领取包时明确返回原因，不无限领包/释放循环。
- 服务端关于重标方法身份的约束保留，不允许通过更换 worker/model 字符串绕过。

验收：同会话排除包不重复返回；冷却到期不覆盖当前会话排除；其他合格工作者仍能领取；人工定向重试行为显式定义；旧客户端释放逻辑兼容。

### P1-B：运行记录和复查产物

将本轮临时导出能力收进正式工具，保存每包标签快照、复核 manifest、提交回执、轨迹图和可选跟球视频。视频只作辅助检查，不代替逐帧原图复核。

记录每包总耗时、搜索/写标/复核耗时、出图页数、工具调用数、改标次数及 absent→visible 修正数。Token 仅在宿主提供可信 usage 时记录，并区分输入、缓存输入和输出；不可用则写 unknown，不按图片数量推算成实测值。账户周额度是共享且可能延迟的指标，不作为单包 token 成本。

## 4. Skill 修改内容

更新 `skills/ball-label/SKILL.md` 及相关引用，保持正文简短，详细工具参数放 references。

| 环节 | 下一版明确规则 |
| --- | --- |
| 冷启动 | 先确认比赛球身份，再连续跟踪；仅凭中圈位置、白色亮点或轨迹候选不足以确认。无法可靠区分则记录原因并释放。 |
| 连续观察 | 平直段先用稀疏目标帧定位，之后补看所有目标帧；触球、反弹、遮挡前后密看。不把插值坐标写成最终答案。 |
| 贴脚球 | 保留球员上下文，必要时 2×显示对照前后帧；球鞋和白线不能凭连续性认作球。 |
| 模糊/遮挡 | 拖影取视觉中心，blurred/occluded 每帧独立判断；部分可见仍可标，完全不可见不猜被挡住的球心。 |
| absent | 确认不是出窗、背景混淆或搜索范围不足后再标；全部 absent 帧做专项复核。未查看保持 missing。 |
| 标后检查 | 从实际保存标签出图，所有目标帧逐页看；再看轨迹是否符合动作；修正后重看受影响页与轨迹。 |
| 领包失败 | 使用结构化原因与会话排除；重复返回已失败包时检查调度，不靠修改身份绕过。 |
| 收尾 | 确认服务端提交成功、保存回执后计为完成；待审核与已验收入库分开统计。用户要求本包后停止时不再领下一包。 |

不新增「每帧写长解释」要求；仅对球身份歧义、定位丢失和异常修正保留简短证据，控制文本开销。

## 6. 验证与下一轮试标

必要测试覆盖 `client/tests/test_views.py`、`test_agent_core.py`、`test_visual_submit.py`、`test_db_lease.py` 及新增共享模块。重点测坐标、复核失效、目标帧覆盖、调度兼容和审核路径，不写只重复说明文字的测试。

试标分两步：

1. **离线回放**：使用已有包覆盖夜场小球、快速传球/反弹、贴脚遮挡、静止球、ERP 接缝及已知漏标帧。不得覆盖历史已提交标签，结果写独立目录。至少完整跑通一包 100 帧的工具链。
2. **新包试标**：先做 3 包、各 100 个目标帧。按正常调度领取，不为获得好结果挑简单包；记录释放包及原因。逐帧视觉复核后进入原有 AI 审核。

人工审核至少覆盖这 300 帧中的全部 absent 帧、全部疑难事件，以及预先固定抽取的可见帧；记录抽样方式和样本数。另对已知回放案例进行独立核查。球心误差阈值在审核前按项目现有口径固定，不能看完结果再选阈值。

对比指标：

- 质量：可见性误判、备用球/球鞋/白线误标、球心误差分布；分开报告回放与新包、抽样与全量结果。
- 流程：目标帧覆盖率 100%，absent 专项复核覆盖率 100%，坐标变换错误为 0，改标后无旧复核凭证误用。
- 效率：每 100 帧耗时、工具调用与出图数量、困难包重复领取次数；可信 token usage 可用时再比较成本。
- 调度：同会话已排除困难包重复领取为 0；下载错误与定位失败分别计数。

上线判断：工程验收全部通过，试标未出现新增的系统性坐标偏移或流程漏检；人工审核显示质量不劣于可比旧流程样本。300 帧只能支持小规模试运行结论，不能宣称泛化准确率提升。若仍出现较多漏标，先调整搜索与 absent 复核；不要用置信分筛掉困难帧来改善表面指标。

## 7. 兼容与回退

- 新工具采用增量接口；先保留现有 `ball_label(roi_xy)` 和 CLI，验证后逐步接入新版 review 提交路径。
- 新调度字段有默认值，旧 reason 能映射；数据库迁移前备份并记录版本，避免不可逆字段删除。
- 共享渲染或复核记录出现问题时，可回退到当前坐标 CLI 加人工逐页复核；不得伪造新版复核确认。
- 需要人工审核结果才能判断效果；此 plan 不承诺仅靠工具改动即可消除模型视觉错误。
