# 足球检测模型：训练与迭代优化方案

2026-10-23。目标：在 8K ERP 全景视频里逐帧输出**比赛球**的像素位置（或「本帧无球」）。最终指标：精度 95%、召回 80%。

本文档是方案，不是已实现的代码。文中 `train/` 下的路径都是规划。

---

## 0. 结论先行：P95 / R80 合理吗

**作为最终目标合理，作为第一版目标不合理**。前提是把口径定死（见 §1），并且验证集要先清洗。

参照系（都在本仓库实测过）：

| 方法 | 精度 | 召回 | 来源 |
|---|---|---|---|
| 旧工作流 v2（VLM 级联） | 约 70% | — | `docs/design.md`，54 帧 |
| Codex 单帧 2× 读点 | 87%（34/39） | 79%（34/43） | `artifacts/label-trials/vlm-compare-20261022/`，命中半径 10 px |
| Codex 2×2 拼页读点 | 95%（36/38） | 84%（36/43） | 同上 |
| 国产模型投票 glm+deepseek | 100%（31/31） | 72%（31/43） | 同上 |
| 入库 GT 帧级审核通过率（Codex gpt-6.1-sol） | 91% | — | `/api/v2/stats` |

所以 **P95 / R80 ≈ 目前最强 VLM 标注员（Codex 拼页模式）的水平**。专用模型能吃到多帧和人的上下文，这个水平是够得着的，而且推理成本比 VLM 低几个数量级。但有三个前提：

1. **GT 本身的噪声会封顶测得的精度。** 入库 GT 帧级通过率 91%，说明 AI 标注里错帧不少。如果验证集里有 3% 的错帧，模型就算完全正确，测出来也到不了 97%。**验证集和测试集必须逐帧人工复核**（§3.4）。
2. **现有 GT 偏向容易的包。** AI 标不下来的包会以 `cannot_locate` / `lost_after_occlusion` 释放，根本进不了 GT。在这样的集合上测 P95 / R80，会高估真实场景的表现。所以要另建一个**难例集**，单独定目标（§1.3）。
3. **口径要分开定**：召回按「GT 可见帧」算，精度按「模型输出了点的所有帧」算，其中包括 GT 无球的帧。

建议按里程碑逐步逼近（§8）：M1 先到 P85 / R60，M2 到 P90 / R70，M3 到 P95 / R80。

## 1. 指标定义

### 1.1 主指标

只在**目标帧**上评，即包里每隔 `step=3` 的 100 帧。这些帧有 GT。

- **命中**：预测点与 GT 点的距离 ≤ r。ERP 横向按环绕距离算：`dx = (x1 - x0 + W/2) % W - W/2`。
- **主半径 r = 15 px**，同时报 10 px 和 20 px。不用 10 px 当主半径，因为球径 8–30 px，近处大球的 GT 中心本身就有几个像素的歧义。
- **精度** = 命中数 / 模型输出了点的帧数。GT 无球的帧上出点、或偏离超过 r，都算错。
- **召回** = 命中数 / GT 可见且非插值的帧数。
- **工作点**：在验证集上扫阈值，取「精度 ≥ 95% 时召回最高」的点，然后在测试集上**原样**复现。不允许在测试集上调阈值。

### 1.2 分场景报告

GT 表里有 `occluded` 字段（现有 7130 个可见点中 700 个标了遮挡）。其余场景从轨迹和人体检测里派生：

| 场景 | 判定 | 现有数据占比（参考） |
|---|---|---|
| 静止 | 相邻目标帧位移 < 2 px | 约 22% |
| 慢速 | 2–48 px / 目标步（≤ p90） | 约 68% |
| 快速 | > 48 px / 目标步 | 约 10%，p99 = 140 px，最大 406 px |
| 遮挡 | `occluded=1` | 约 10% |
| 贴人 | 距最近人体框 < 1 个球径（需人体检测） | 待统计 |

### 1.3 难例集目标

从释放过的难包里抽包，由人工标注组成难例集。目标单独定为 **P90 / R60**，只跟踪趋势，不作为上线门槛。

### 1.4 包级指标

- **换球率**：比赛球 query 跳到备用球或其它物体、并持续 ≥ 3 个目标帧的包占比。目标 ≤ 2%。
- **断轨**：GT 连续可见、而模型连续漏掉 ≥ 5 帧的段数 / 包。

### 1.5 统计量

同一个包里的帧高度相关，所以置信区间要**按包自助采样（bootstrap）**，不能按帧算二项分布。按 `docs/design.md` 的经验，54 帧规模下同一配置重复跑的波动约 ±3 个点。验证集至少要 15 个包、约 1500 个可见点，才分得清 1–2 个点的差异。

## 2. 数据

### 2.1 现状（2026-10-23）

- 已入库 76 个包、24 个场次（`group_name`，按日期分），7130 个可见点；其中人工 1850 个、AI 5280 个，插值 1178 个（16.5%），无球帧 518 个。
- 每个包：`clip.mp4` 是 ROI 裁剪，原分辨率，约 4000×2080，300 帧，30 fps，约 10 秒；另有 `dog.mp4` 和 `meta.json`（`roi`、`pano_size`、`targets`、`step=3`）。
- 全景统一为 7680×3840。球 90% 落在 y = 1900–2400 的带里（`artifacts/label-dist-20261023/ball-distribution.png`）。
- 72 个 accepted 包里，52 个由 Codex 标注，19 个来自旧导入或人工。

### 2.2 规模里程碑

单位是**包和场次**，不是点：同一个包里的 100 个点高度相关。

| 阶段 | 包 | 场次 | 可见点 | 用途 |
|---|---|---|---|---|
| 现在 | 76 | 24 | 7.1k | 只够打通流水线、训对照组 |
| M1 起步 | ~150 | ~40 | ~14k | 留出 6–8 个场次做验证；模型主要学外观和短时运动 |
| M3 上下文 | 400–500 | 80+ | 40–50k | Transformer 的慢路才学得到人的行为 |

扩数据时，**优先增加场次，而不是在已有场次里加包**。场地、光照、机位的多样性比同一场的更多片段更值钱。

### 2.3 导出与格式

在 `scripts/export_gt.py` 上加一个 `--train-format` 输出（规划）：

```
data/ball_v{N}/
  index.jsonl            每包一行：packet_id, group, split, roi, n_visible, source 分布
  labels/<packet_id>.jsonl
                         每目标帧一行：frame_idx, local_x, local_y（ROI 内坐标）,
                         pano_x, pano_y, visible, occluded, interp, source, conf, weight
  ignore/<packet_id>.jsonl
                         备用球等忽略区：frame_idx, local_x, local_y, r
```

视频不重新编码，训练时直接解码 `clip.mp4`。导出只追加新版本，旧版本只读，这样每次训练都能对上数据版本。

### 2.4 划分

- **按场次（group）划分**，同一场次的包只能全部进同一个集合。
- 训练 / 验证 / 测试 = 约 70 / 15 / 15，按场次计；分层时要让室内外、白天夜间、机位类型分布大致平衡。
- 验证集和测试集**冻结**：新数据只进训练集；需要扩验证集时另起 `val_v2`，不改旧的。
- `dual_m3` 这类非比赛日期命名的组单独审一下来源，再决定放进哪个集合。

### 2.5 标签处理

| 情况 | 处理 |
|---|---|
| 人工 / 审核通过的 AI 可见点 | 正样本，权重 1.0 |
| 插值点（`interp=1`） | 正样本，权重 0.3 |
| GT 无球帧 | 整帧负样本（热力图全 0，存在分支 = 0） |
| 遮挡但标了位置 | 正样本，权重 1.0；单独统计 |
| 场边备用球、球门后的球 | **忽略区**：热力图上半径 20 px 内不计损失 |
| 伪标签（§7.3） | 正样本，权重 0.5 × 置信度；永远不进验证 / 测试集 |

**备用球需要改标注规范**：现在只标比赛球，备用球在训练数据里就成了背景。这会教模型「球的外观不是球」。要在标注工具里加一个「其它球」标记（只需点一下，不要求逐帧），导出成忽略区。这是 M1 之前要做的标注侧改动。

### 2.6 未标注的帧

每包 300 帧里只有 100 帧有 GT。中间 200 帧是相邻两帧 GT 之间的原始帧，有两个用途：

- **快路输入**：短时窗口按原始帧取，间隔 1 帧，能看到连续运动。
- **弱监督**：两侧 GT 都可见、且位移 < 48 px 时，中间帧用线性插值当软标签，权重 0.2。弹地、碰人时线性插值不对，所以快球段不用。

## 3. 模型

### 3.1 总体结构

```
输入：ROI 原分辨率裁剪（训练 768–1024 px 块；推理滑窗铺满整条带）
  │
  ├─ 逐帧共享骨干：SAM2.1 Hiera（预训练），stride 4 / 8 / 16 / 32 四级特征
  │    每帧算一次并缓存；推理时相邻窗口复用
  │
  ├─ 快路 @ stride 8：T_fast = 7 帧原始帧（间隔 1，约 0.23 s）
  │    时空窗口注意力（窗 8×8×T，Video Swin 式，横向 roll 实现 ERP 环绕）
  │    + 1 层可变形时间注意力（每个位置学偏移，去邻帧采样）
  │    → 球的外观、模糊、短时运动
  │
  ├─ 慢路 @ 原图 stride 32：T_slow = 32 帧（间隔 2，约 2.1 s）
  │    输入降采样 4× 后过同一骨干，取 stride 8 特征（等价原图 stride 32）
  │    时空窗口注意力（窗 16×16×8，时间维逐层下采样）
  │    → 人的行为：跑位、阵型移动、谁在朝哪里冲
  │
  ├─ FPN 解码：慢路上采样注入快路，再和 stride 4 特征融合
  │    → 中心帧 ±3 帧的热力图（stride 2）+ 亚像素偏移 + 每帧「有球」分支
  │
  └─ 比赛球 query：1 个 track query 读解码特征，跨窗口传递状态
       → 唯一比赛球的位置与可见性
```

### 3.2 关键尺寸的依据

- **快路用原始帧、间隔 1**：现有 GT 里球的位移中位数是 9 px / 目标步（3 个原始帧），p99 是 140 px，换成单帧约 3 px 和 47 px。stride 8 下 p99 约 6 个 token，8×8 的窗基本盖得住；剩下 1% 的极快球交给可变形注意力。
- **骨干第一级是 stride 4**：8 px 的球在 stride 4 上还有 2×2 个点。ViT 式的 16× 切块会把球揉进一个 token。
- **慢路降采样 4×**：一个人在画面里有几十到几百 px 高，降 4× 后仍然看得清，而每帧算力只要 1/16。
- **ERP 环绕**：卷积用横向循环填充，窗口注意力的 shift 用 `roll`；推理时整条带横向首尾相接，接缝就成了普通位置（约 46% 的场地跨接缝）。

### 3.3 参数量

| 模块 | M1（Hiera-T） | M3（Hiera-S） | 训练方式 |
|---|---|---|---|
| 骨干 | ~20–25M | ~35M | 预训练；先冻结，再按层衰减学习率解冻 |
| 快路 | 2 层，dim 192，~2M | 3 层，~3M | 从零 |
| 慢路 | 2 层，dim 384，~4M | 4 层，~7M | 从零 |
| 解码 + 各头 | ~2M | ~3M | 从零 |
| 比赛球 query | ~1M | ~2M | 从零 |
| **合计** | **~30M** | **~50M** | 从零部分 ~9M / ~15M |

数据到 50k 点之前不上 100M 以上的模型。容量优先加在预训练骨干上，从零训练的模块保持小。

### 3.4 对照组

所有消融都在同一份数据、同一个验证集、同样的裁剪下跑：

1. **卷积热力图对照**：HRNet 式（WASB 风格），参数量同级，同样的多帧输入。
2. **去掉慢路**：量「人的行为」到底贡献多少。
3. **去掉比赛球 query**：改用热力图峰值 + 轨迹解码选球。
4. **加不加差分 / DoG 输入通道**：显式运动线索在小数据下可能帮很大。

## 4. 预训练

不合成假球：贴上去的球和真实球员的行为对不上，会破坏「人的行为 → 球的位置」这条信号。

| 阶段 | 数据 | 目标 | 作用 |
|---|---|---|---|
| P0 | 无，直接用 SAM2.1 Hiera 权重 | — | 细粒度视觉特征 |
| P1 掩码视频建模 | 全部已产包 + 原始视频的球场带（无需标注） | VideoMAE 式重建被遮挡的时空块，遮挡率 75–90% | 让时间模块在真实比赛上学到运动规律 |
| P2 人体辅助任务 | 同上，人体框由现成人体检测器离线生成 | 预测人体中心热力图 | 让慢路学会读站位和跑动 |

P2 的人体头在正式训练时保留，作为辅助损失（权重 0.1），推理时丢掉。

## 5. 训练

### 5.1 损失

| 头 | 损失 | 权重 |
|---|---|---|
| 球热力图（stride 2，σ = 2.5 个输出像素 ≈ 5 px） | CenterNet focal（α=2, β=4），忽略区不计 | 1.0 |
| 亚像素偏移 | L1，只在正样本位置 | 1.0 |
| 每帧有球 | BCE | 0.5 |
| 比赛球 query 位置 | L1（ROI 坐标归一化），只在可见帧 | 1.0 |
| 比赛球 query 可见性 | BCE | 0.5 |
| 人体热力图（辅助） | focal | 0.1 |

单个样本的损失再乘上 §2.5 的标签权重。

### 5.2 采样

- 每个样本 = 一个包里的一个中心帧 + 快 / 慢两个时间窗口 + 一个空间块。
- 2/3 的块保证包含球（球在块内随机位置，离边缘 ≥ 64 px），1/3 是带内随机块。
- 从第 5 个 epoch 起，每个 epoch 末把验证集以外、训练集里的高分误检位置收进难负样本池，下个 epoch 按 20% 的比例采。
- 包之间均匀采，不按点数加权：不能让长时间可见的包霸占训练。

### 5.3 增强

| 增强 | 说明 |
|---|---|
| 水平翻转 | ERP 翻转后几何仍成立 |
| 颜色抖动、高斯噪声 | 亮度 ±20%、对比度 ±20% |
| 重编码 | 随机 H.264 CRF 18–28，模拟不同码率 |
| 帧率抖动 | 快路间隔在 1–2 之间随机 |
| 小幅缩放 | 0.8–1.25；更大的缩放会破坏「球的大小 ↔ 距离」信息 |
| 时间倒放 | 概率 ≤ 10%：人的行为倒放后不合理，不能多用 |

不做：粘贴合成球、大幅透视变换、马赛克拼图。

### 5.4 超参（起点）

- AdamW，wd 0.05；头部和时间模块 lr 2e-4，骨干 lr 2e-5，按层衰减 0.8。
- 预热 1k step，余弦退火；bf16 + 梯度检查点。
- 块 768×768，T_fast = 7，T_slow = 32；单卡 batch 2–4（24 GB），4–8 卡数据并行。
- 两段式：
  - 第一段冻结骨干，约 20 epoch，只训时间模块和头部；
  - 第二段全网解冻，约 40 epoch，按验证集上 P95 工作点的召回挑选 checkpoint。

## 6. 推理与后处理

1. ROI 带滑窗（块 1024，重叠 128），横向环绕；每帧的骨干特征算一次后缓存。
2. 快路窗口以步长 3 滑动，每个窗口输出中心 ±3 帧，重叠帧的热力图取平均。
3. 每帧取 3×3 NMS 之后的前 8 个峰值作为候选。
4. **比赛球 query 是主输出**；query 可见性低、但候选里有高分峰时，退回轨迹解码：在候选上跑 Viterbi，速度上限 450 px / 目标步，与标注链路的约束一致。
5. 输出：每帧 `(pano_x, pano_y, score, visible)`，加上包级换球标记。
6. 阈值只在验证集上定（§1.1）。

## 7. 迭代闭环

### 7.1 每轮流程

```
导出 GT（ball_v{N}）→ 训练 → 在冻结的 val / test / hard 上评测 → 出报告
      ↑                                                          │
      │                                                          ▼
 人工复核 ← 挖难例和疑似错标 ← 模型上线当提名器 / 预标注 ← 达到当前里程碑门槛
```

建议节奏：每增加约 50 个包或每两周跑一轮，以先到者为准。每轮报告写到 `artifacts/detector/v{N}/report.md`，并在日更里登记。

### 7.2 模型反哺标注

- **替换 `propose`**：DoG blob 的提名在球贴脚下时召回约 8%，是标注链路最弱的一环。模型的前 8 个候选直接作为 `ball_scan` / `ball_view` 的提示，Codex 和投票标注的成本和失败率都会下降。
- **预标注**：达到 M2 后，模型的整包输出作为初值，Codex 或人只做审核和修正。

### 7.3 伪标签

- 在未标注的包上跑模型；只取同时满足以下条件的轨迹段：速度一致、query 可见性 ≥ 0.9、热力峰 ≥ 0.7、长度 ≥ 10 个目标帧。
- 按 §2.5 降权进训练集。伪标签占比不超过人工 + 审核 GT 的 1 倍。
- 伪标签只进训练集，**永远不进验证 / 测试集**。

### 7.4 主动学习

每轮从未标注池里挑以下三类包，优先送人工标注：

1. 模型置信度低的包；
2. 比赛球 query 和轨迹解码结果对不上的包；
3. AI 标注员释放过的难包（`cannot_locate` / `lost_after_occlusion`）。

### 7.5 用模型挖 GT 错标

模型高分、但和 GT 偏差 > 30 px 的帧，送审核页复核。它们往往是 GT 错了。这一步直接决定 P95 量不量得出来：验证集错标 3%，测得的精度上限就只有约 97%。

## 8. 里程碑与门槛

指标口径见 §1：主验证集，r = 15 px，按包 bootstrap 取 95% 置信区间。

| 里程碑 | 数据 | 模型 | 门槛（主集） | 难例集 | 上线 |
|---|---|---|---|---|---|
| **M0 打通** | 现有 76 包 | 卷积对照 + Hiera-T 小版 | 能复现、有基线数字 | — | — |
| **M1 起步** | ~150 包 / 40 场次；备用球忽略区已加 | Hiera-T，~30M | P ≥ 85，R ≥ 60 | 只记录 | 替换 `propose` 当提名器 |
| **M2 扩充** | ~300 包 / 60 场次 + 伪标签 | Hiera-T 或 S | P ≥ 90，R ≥ 70；换球率 ≤ 5% | P ≥ 80，R ≥ 45 | 预标注 |
| **M3 目标** | 400–500 包 / 80+ 场次 | Hiera-S，~50M | **P ≥ 95，R ≥ 80**；换球率 ≤ 2% | P ≥ 90，R ≥ 60 | 主力标注，人只审核 |

每个里程碑还要附带：

- 去掉慢路的消融。如果慢路对召回的提升 < 2 个点，说明数据还不够模型学到上下文，**先扩数据，不扩模型**。
- 分场景表（§1.2）。快速和贴人两档通常是瓶颈，要单独看趋势。

---

## 9. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 验证集 GT 有错帧 | 测得的精度被封顶 | 验证 / 测试集逐帧人工复核（§7.5） |
| GT 偏易 | 主集指标虚高 | 单独的难例集；主动学习优先标难包 |
| 备用球被当背景 | 召回低、换球 | 标注加忽略区（§2.5） |
| 场次少导致域偏移 | 新场地掉点 | 扩数据优先扩场次；按场次划分 |
| 极快球（> 300 px / 目标步） | 窗口和可变形注意力都跟不上 | 单独统计；必要时对快路加大时间分辨率 |
| 球出界、门将抱球 | 「比赛球」的定义变模糊 | 标注规范补充：被手持的球仍算可见 |
| 慢路训练显存 | 32 帧 × 块 | 降采样输入 + 梯度检查点；必要时 T_slow = 16 |
