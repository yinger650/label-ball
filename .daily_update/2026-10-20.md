## 16:40 调研 TypeSafe Jev 能否用于 AI 标球（未接入、未实测）

- **结论**：Jev 是"决策模型"，不生成文本，只回答 choice / noul（是非）/ score / box，每个答案带校准概率；`POST https://api.typesafe.ai/v1/systemone`，**不兼容 OpenAI**，要在 `client/vlm.py` 另写适配。图片和 box 是 1.14（2026-10-14）的实验功能，需 header `TypeSafe-Danger-Zone-Images: true`，官方称多模态弱于纯文本、未达生产标准。
- **契合点**：答格子号 = choice（每格一个概率），"看不见" = noul，可直接接 verify 门阈值；官方推荐的大图搜索用法就是切格子做 choice、逐级放大。按输入 token 计费 $0.042/M，单图约 3.8k token，亚秒级返回。
- **限制**：单图边长 280–1568 px，超出直接拒绝不缩放（`ball_strip` 出图 320–720 px，满足）；box 没有"找不到"，必须配 noul；不擅长计数和多跳推理；不能当 MCP agent 驱动整包流程。
- **建议**：先接成 `voter` / 判空角色，用 `scripts/bench_v2v3.py` 对比 v2 + glm53 基线（有种子扁 ROI 87% / 45% / 4.0 px）。

## 16:50 AI 标球 harness 选型：现成 harness vs DeepSeek Harness（dsh）

- **背景**：用户反馈 gpt6-astra 直接操作人工 UI 效果好，固定流程配其他模型效果差；人工也要看多张图才能定位。
- **dsh 调研**：开源（MIT），developer preview，会有不兼容改动。agent 循环、模型适配、工具注册都是可替换插件；`@deepseek-ai/dsh-mcp-client` 支持 stdio / streamable-http，模型声明 `input: [text, image]` 后，MCP 工具结果里的图片会原样交给模型。`client/mcp_server.py` 出图是标准 MCP image 块，可直接接。多家模型走 `llm-pi-ai`（OpenAI 兼容、Anthropic 等）。社区的 `dsh-vision-provider` 是"视觉模型转文字描述再给 DeepSeek"，会丢掉小球像素信息，不能用。
- **结论**：工具层固定为 `ball-label` MCP；先用 Codex + astra 在 16 个 accepted 包上量化，和"操作 UI"对比，确定瓶颈在工具出图还是 harness；需要换模型跑量 / 控成本 / 可复现 bench 时，再用 dsh 挂同一个 MCP 做多模型对比。
